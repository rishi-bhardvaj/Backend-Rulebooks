# Research and Threat Modeling

Before security-sensitive implementation, inspect authoritative project/framework/security documentation and the existing repository. For application security, use OWASP ASVS as a verification-oriented reference where applicable.

Do not copy external rule libraries verbatim. Extract concepts, adapt them to this framework-neutral system, and record important inspirations in documentation. Identify assets, actors, trust boundaries, abuse cases, and security controls before coding when risk warrants it.
